Verdict

Semrush uses a summary dashboard to tell the site owner what changed and where to investigate. Clarity uses an evidence explorer to show where people clicked, stopped scrolling, or spent time. The SEO Tool should keep these as two linked report types rather than forcing both into one screen.

Top action: build a compact SEO Overview first, then let each finding open a Behavior Heatmap report with the same date, URL, device, and segment context.

1. Semrush SEO Dashboard

The linked Semrush project requires a Semrush login, so its private project values were unavailable. The interface structure was visible, and the features below were verified against Semrush's official SEO Dashboard documentation.

Purpose and information model

  • Purpose: a small analytics report that summarizes the current SEO state of one project.
  • Structure: independent widgets show excerpts from larger Semrush tools. Each widget has a setup state, summary state, and a View Full Report action.
  • Behavior: widget refresh times differ because each source tool updates on its own schedule.

Project controls

  • Project selector and direct link to the tracked website.
  • Sharing count for the project.
  • Settings for Google account connections, competitors, tags, project name, and deletion.
  • Set Up actions for tools such as Site Audit and Position Tracking when no campaign exists.

Observed TrendWatching behavior

  • Last three days: no clicks were available for the PC homepage view. Clarity recommended widening filters or changing the device.
  • Thirty days: 43 PC page views produced 3 clicks across three elements, one click each. The sample is too small for a confident content decision.
  • Rage clicks: no rage-click elements appeared over 30 days.
  • Scroll: 67.44% of visitors reached 10% depth, 18.60% reached 20%, 6.98% reached 35%, 4.65% reached 50%, and no visitor reached 70%.
  • Attention: the first 10% of the page held 55.51% of measured session time. The 35% to 40% band held another 17.25%.

The linked URL included rageClickCount=1, which Clarity displayed as a session filter that does not work with Heatmaps. Rage-click heat should be selected from the Click subtype menu. This explains the initial empty state.

4. Design blueprint for SEO Tool

Report A: SEO Overview build first

  • Header: project, domain, date range, comparison period, last refresh, and data-source status.
  • Summary row: organic traffic, clicks, impressions, average position, site-health score, referring domains, and tracked keywords.
  • Finding cards: one chart, one sentence explaining the change, one recommended action, and one Open report link.
  • Widget states: loading, connected, stale, low data, error, and setup required.
  • Drill-down: keep the selected date, domain, device, country, and comparison when opening a detailed report.

Report B: Behavior Heatmap

  • Top context bar: URL match rule, date range, segment, device, and comparison.
  • Mode bar: all, dead, rage, error, first and last clicks; scroll; attention; area.
  • Left panel: ranked elements for click modes, data tables for scroll and attention, and recording links.
  • Canvas: page screenshot with heat overlay, markers, zoom, opacity, and screenshot selection.
  • Evidence footer: sessions, page views, clicks, sample cap, data freshness, and color legend.

Shared behavior rules

  • Every chart prints its exact values in text or a table.
  • Filters persist when users move between overview and detail.
  • Low-data states explain the threshold and suggest a specific broader range.
  • Each finding links to its source data and shows when that source refreshed.
  • Comparison uses the same metric and unit on both sides.
  • Save useful filter combinations as named segments.

Suggested product flow

1. ScanSEO Overview highlights material changes and setup gaps.

MVP boundaries

Start with six SEO widgets and four behavior modes: all clicks, rage clicks, scroll, and attention. Add dead clicks, error clicks, area editing, conversion maps, and side-by-side compare after the core filter state and data-quality messaging are reliable.

What to do next

  1. Create the SEO Overview shell with project context, shared filters, KPI cards, and six widget states.
  2. Build the Heatmap report as a two-panel workspace with one URL, one device, and four initial modes.
  3. Pass date, URL, device, and segment context between both reports so a user can move from a ranking change to page behavior without rebuilding filters.
  4. Test all empty states with real low-volume pages. The TrendWatching example shows why this is part of the main experience, not an edge case.
