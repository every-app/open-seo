What the current backend actually provides

Code inspection and local run · September 19, 2026 · branch dev-seo

Verdict: This is a substantial application backend, not a front-end mockup. Its database, authentication, SEO API, Google integrations, audits, rank tracking, and saved reports already have server code. The current local login and new DGTL overview are demonstrations; they do not prove that client onboarding or live data is configured.

First action: Move a staging deployment to hosted authentication with a real database, email delivery, and two isolated test clients before inviting customers.

How one request reaches data

1. Browser requests a project page→2. Session, role and project membership checked→3. Server function validates input→4. Service and repository read the tenant's data or provider API

The code has separate project authorization middleware and organization permission checks. The super-admin read function also checks the signed-in email on the server, so hiding a navigation link is not its only access control.

What is running locally today

  • The Vite development server returned HTTP 200 at http://127.0.0.1:3001/ on September 19, 2026.
  • .env.local selects AUTH_MODE=local_noauth, VITE_DGTL_DEMO_AUTH=true and PORT=3001. This is for local demonstration only.
  • The environment contains an OpenRouter key for AI functions. The key value was not read or copied into this report.
  • No DataForSEO, Google OAuth, Loops or Clarity credential names were found in this local environment. The report did not test any live provider account.

Hosted signup remains available in the upstream auth flow, and the current team invitation function grants the organization-admin role. An invitation-only client service with read-only client roles needs explicit server-side changes before launch. The package.json name and several Worker resource names still use OpenSEO; changing persistent D1 identifiers requires a migration plan, not a cosmetic rename.

Limit: Source code and an HTTP 200 response establish that the app starts. They do not establish that production migrations, delivery, permissions and connector refreshes have passed an end-to-end test.
