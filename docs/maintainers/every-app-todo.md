# OpenSEO on Every App: follow-ups

Open decisions and follow-ups for OpenSEO on Every App (`AUTH_MODE=everyapp`, [every-app.md](every-app.md)); each section is one review, newest first. Written against the port's private repository before it merged into this one, so file paths and PR numbers refer to that history.

## First run (2026-10-24)

What the first-run walk of http://openseo.localhost:8788 left open after the small PR (`first-run-2026-10-24`). Owner in parentheses when it is not this app.

- [ ] **First site scan falls back to unrendered when CONTEXT_API_KEY is absent.** DashboardFirstAuditService.start and AuditHealthCard always send renderJavaScript:true, so on Every App every "Add your website" and "Scan my website" ends in a failed-scan toast while an unrendered audit of the same site runs fine. Use `renderJavaScript: await isAuditRenderingAllowed()` in both and keep "Your 50-page site scan is running". (openseo-04)
- [ ] **Decide: set CONTEXT_API_KEY on everyapp.team before Monday, or ship openseo-04 first.** DATAFORSEO_API_KEY and OPENROUTER_API_KEY are required by the manifest, so most refusal surfaces disappear once they are set; CONTEXT_API_KEY is optional, so without it (or openseo-04) every member's first scan fails on Monday. (decision for Ben, openseo-39)
- [ ] **Dashboard "new links" card shows "Too many requests" for 5 minutes after a DataForSEO refusal.** DashboardCacheService.readThrough holds a 5-minute claim after a failed refresh and throws RATE_LIMITED while it is held, so a member opening the dashboard right after a teammate sees a red "Too many requests" card instead of the setup message. Skip the refresh when hasDataforseoAccess() is false, or rethrow the original DATAFORSEO_AUTH_FAILED while the claim is held. (openseo-03)
- [ ] **Agent setup page and copied prompt point at the gateway connector.** The copied installer prompt tells the agent to add the app-host /mcp, to "Prefer OAuth", to visit a Settings → API keys page that does not exist, and to install the hosted plugin; the gateway connector is only a small alert at the bottom. Make the gateway URL (gatewayUrl + "/mcp", tools as `openseo_*`) the copyable primary in Every App mode, also on the dashboard "Connect your AI agent" step. (openseo-08)
- [ ] **SAM gate: ask the gateway whether OpenRouter is really set, and word the turn failure.** getSamAccessSetupStatus answers enabled:true whenever the gateway binding exists, so in production the gate never shows and the first message fails with "SAM stopped before finishing this reply." and a Retry that always fails; in dev the gate shows self-host wording. Needs the readiness call below plus copy: "SAM needs OpenRouter on your Every App gateway. An owner or admin sets it with pnpm everyapp secret set OPENROUTER_API_KEY, then press Check again." (openseo-07, merged with openseo-30)
- [ ] **An AI-provider readiness call, like integrationStatus for capabilities.** Apps have no way to ask whether the gateway holds OPENROUTER_API_KEY before the first model call. SAM (openseo-07), the AI-visibility pre-check (openseo-06) and /api/health (openseo-34) all need it. (SDK, openseo-30)
- [ ] **AI visibility: pre-check the gateway and store the provider refusal as the failure reason.** Check DataForSEO (hasProviderAccess) and OpenRouter before "Start research" and replace the button with the setup sentence; map the workflow's 503 ai_provider_not_configured / integration_not_configured to a stored failure (like website_unreadable) so the failed state names the key instead of the copy-only sentence the PR ships. (openseo-06)
- [ ] **Prompt Tracking gate passes when a tracker or prompts already exist.** An agent that saved prompts via save_ai_visibility_tracker leaves the person on the research gate forever, because getAiResearchSetup is "ready" only when research keywords exist; the tracker editor and its DataForSEO notice are unreachable. (openseo-11, merged with openseo-24)
